# Рефакторинг великих файлів Vertep CORE

Усі незакомічені етапи рефакторингу об’єднано у версію `0.0.1.12` після commit `0.0.1.11`.

## Карта модулів

| Версія | Модуль | Призначення |
|---|---|---|
| 0.0.1.11 | `core/api/setup.py` | First Run Wizard |
| 0.0.1.12 | `core/api/job_helpers.py` | Спільні допоміжні функції job та task |
| 0.0.1.12 | `core/api/jobs.py` | Життєвий цикл job, артефакти, імпорт та експорт |
| 0.0.1.12 | `core/api/tasks.py` | Отримання, поновлення, результати та повторні спроби task |
| 0.0.1.12 | `core/api/workers.py` | Heartbeat, перелік та стан worker |
| 0.0.1.12 | `core/api/nodes.py` | Реєстрація вузлів, керування та credentials |
| 0.0.1.12 | `core/api/observability.py` | Health, метрики, сповіщення, журнали та обслуговування |

## Межі рефакторингу

У `core/app.py` залишаються middleware, lifespan, watchdog, системні й Telegram маршрути, керування Telegram polling та підключення router. Публічні імпорти збережено для сумісності.

`core/api/system.py` та `core/api/telegram.py` — заготовки наступного перенесення, не підключені до API. `TelegramServiceHolder` у `core/state.py` також підготовлено для наступного етапу; поточний polling використовує стан у `core/app.py`.

Маршрути вузлів і моніторингу підключено один раз через відповідні router зі збереженням попередньої поведінки. Тести перевіряють відсутність повторів пар HTTP method + path і керування станом вузла.

## Версія та перевірки

`VERSION`, `CHANGELOG.md` та `releases/0.0.1.12.md` описують одну версію. Історія Git залишається незмінною. Перед commit виконуються `compileall`, `pytest` та `git diff --check`.
