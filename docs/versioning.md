# Версіонування та публікація Vertep

> Статус: чинний | Аудиторія: розробник, агент | Канон: [AGENTS.md](../AGENTS.md) §2.

## Формат

`A.B.C.D` — послідовна нумерація: кожна нова версія збільшує останній компонент поточної `VERSION` (`…0.0.1.99 → 0.0.2.0`). Один commit у `main` = одна версія; назва версійного commit — лише номер (`0.0.1.70`, без суфіксів).

## Склад версії

Один commit містить: код, конфіги, тести, документацію, оновлений `VERSION`, блок `CHANGELOG.md` (`## ПРАВИЛЬНА НАЗВА: <версія>` + пункти українською) і `releases/<версія>.md` (заголовок `# Vertep <версія>`). Роздільні коміти під `VERSION`/`CHANGELOG`/нотатки і автокоміти після версійного — заборонені. Історія не переписується (ніколи: ні rebase/amend/push --force, ні рухомі tags).

## Три команди власника

- **`пуш`**: нова версія → release-файли → compileall + diff check → один commit із `[skip ci]` → push main → STOP. Локальні тести заборонені; tag/Release не створюються.
- **`тест`**: та сама підготовка з повним `python -m pytest -q -n 8 --dist loadgroup`; commit без `[skip ci]`, після push запускаються CI і Browser E2E. Без tag/Release.
- **`реліз`**: за брудного дерева спершу повна логіка `тест`; за чистого — чинний commit без нової версії. Перевірити CI/Browser gate точного SHA, потім GitHub Actions release workflow та його артефакти.

`scripts/release.py` — окремий технічний інструмент із власними опціями; він не є синонімом жодної з цих чат-команд. Наявність script не надає дозволу на його commit/push і не скасовує канон §2. Його поточний шлях підготовки використовує `Unreleased` та власний набір тестів; перед застосуванням необхідно звірити поведінку з дорученням. У межах документаційного #448 його реалізація не змінюється.

## Workflow і gate

Release workflow працює з конкретним commit: тести → Docker images (один SHA, теги = `VERSION`) → `vertep-runtime-<версія>.tar.gz` → manifest/checksums/SBOM/підпис → перевірка артефактів → публікація. Browser E2E gate для точного SHA має бути green. Помилка workflow версій не створює; виправлення — новим `пуш` з наступною версією.

Завдання щодо версіонування й release workflow ведуться в GitHub Issues. Деталі артефактів — `release-contract.md`.
