# Реліз 0.0.0.90

## Нова функціональність

### Постійне зберігання налаштувань Telegram

Раніше налаштування `TELEGRAM_ALLOWED_CHAT_IDS` та `TELEGRAM_ADMIN_CHAT_IDS` зберігалися лише у змінних оточення (`os.environ`), що означало їх втрату після перезапуску Core. Тепер ці налаштування зберігаються в постійному сховищі `config/telegram-settings.json` з permissions `0600`.

- Створено модуль `core/telegram_store.py` з функціями `load_telegram_settings()`, `save_telegram_settings()`, `get_allowed_chat_ids()`, `get_admin_chat_ids()`, `is_admin_chat()`, `is_allowed_chat()`.
- Оновлено `core/app.py`: функції `telegram_setup()`, `telegram_status()`, `telegram_webhook()`, `_process_telegram_update()`, `_admin_chat_ids()`, `_is_admin_chat()` тепер використовують постійне сховище.
- Функції `get_admin_chat_ids()` та `get_allowed_chat_ids()` мають fallback на `os.environ` для зворотної сумісної роботи.

### Вибір персонажа у Telegram

Коли користувач надсилає тему в Telegram, тепер пропонується послідовний вибір:

1. **Бренд** — коли є налаштовані бренди, користувач обирає бренд.
2. **Персонаж** — після вибору бренду (або безпосередньо, якщо брендів немає), користувач обирає персонажа зі списку.
3. **Створення задачі** — задача створюється лише після вибору персонажа.

Якщо персонажів немає, використовуюється персонаж за замовчуванням (`did_samogon`).

- Додано новий callback action `select_character` у `_handle_telegram_callback()`.
- Додано функції `_send_character_selection()` та `_handle_character_selection()`.
- Оновлено `_handle_brand_selection()` щоб запропонувати вибір персонажа замість створення задачі.
- Оновлено `_create_job_from_telegram()` щоб приймати необов'язковий параметр `character_id`.
- Оновлено `_handle_telegram_message()` щоб використовувати `_telegram_pending_character` для зберігання даних після вибору бренду.

### Приховання токену Telegram у Web UI

Поле вводу `TELEGRAM_BOT_TOKEN` у Web UI тепер відображає `••••••` коли токен вже налаштований, замість порожнього значення.

### Індикатор черги ролей у Web UI

Коли `deployment-request.json` створено (після додавання нових ролей), у панелі налаштувань ролей відображається статус "Заявка в черзі на застосування ролей...".

- Додано поле `queued` у відповідь API `/api/system/roles`.
- Оновлено `renderRoleSummary()` у `web/admin-uk.js` щоб відображати статус черги.
