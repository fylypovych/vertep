# Vertep 0.0.2.50

## Issue #116 (i.0.0.1.16) — Models: виправити terminal status і cancellation model pull

### Локальний pull (`core/pull_executor.py:_pull_model`)
- Додано HTTP timeout: 300 секунд total, 10 секунд connect — запобігає завислим streams при мережевих проблемах.
- NDJSON error event від Ollama (`{"error":"model not found"}`) негайно викликає `fail_operation` — операція стає `FAILED`, а не `COMPLETED`.
- Cancellation через `cancel_pull` викликає `cancel_operation` — операція durable стає `CANCELLED` (раніше лише audit entry).
- Після EOF потоку перевіряється прапорець `error_received`: якщо error event був — операція стає `FAILED` з повідомленням "pull ended with error event" / "premature EOF after error"; інакше — `COMPLETED`.

### Node pull path (`core/pull_executor.py:ingest_model_progress`)
- Додано thread-safe `_OPERATION_ERROR_STATE: dict[str, bool]` з `_ERROR_STATE_LOCK` для відстеження error стану на кожну операцію.
- Коли node raportує `FAILED` або error у progress — операція позначається як маюча error.
- Коли node raportує `COMPLETED` — перевіряється prior error: якщо був — операція стає `FAILED` ("completed after error"); інакше — `COMPLETED`.
- Коли node raportує `CANCELLED` — error state очищується.

### Worker-side pull (`worker/service.py:_run_model_command`)
- Додано timeout (300s total, 10s connect) до stream запиту до Ollama — запобігає stale streams на worker nodes.

- `tests/test_model_lifecycle.py`: orphaned local pull reconciliation FAILED, local pull без Ollama FAILED.
