# Vertep 0.0.4.30

- Publisher в окремому контейнері (рішення власника, #510/#511): публікацію винесено з воркера в `publishers/runner.py`; контейнер-модуль `modules/publisher/app/` лише завантажує на платформи з обліковими даними задачі, які передає воркер-власник задачі (оновлені токени повертаються в CORE); воркер передає контейнеру завантаження, коли той готовий на вузлі, інакше працює чинний шлях. Компонентний реліз `publisher.0.0.3.92` — образ `vertep-module-publisher` і підписаний пакет; перехід із ролі в контейнер через Центр оновлень, нові права погоджуються разом із планом або профілем доступу.
- Каталог модулів показує встановлений пакет оновленого офіційного модуля, а не копію з релізу; Publisher у контейнері не вимагає ролі на вузлі.
- Update Manager (#512): крок CORE виконаний лише за точної погодженої версії; інша версія або збій Update Agent зупиняють план до кроків модулів.
- Відновлення оновлення модуля (#513): блокування записів знімається лише для перевіреної відновленої версії; невдалий restore чи перевірка лишають його й позначають модуль для уваги.
- Відкат із панелі (#515): відновлена версія, що не пройшла перевірку, — це невдалий відкат із записом UPDATE «rollback to point failed», відповіддю 409 і журналом у панелі.
- CI: перелік issue реального приймання звірено з GitHub (закритий #516 прибрано).
