# Vertep 0.0.1.74

## Monitoring: persistent alerts

Додано `core/alert_store.py` — durable entity для alert з stable id/source/job/node, життєвим циклом `firing → acknowledged → resolved`, acknowledge із фіксацією actor/time, retention і dedup за entity-ключем. `/api/alerts` переписано на цей store: recovery розвʼязує alert і зберігає історію (а не стирає), додано кінцевий `POST /api/alerts/{id}/acknowledge`.

## Monitoring: readiness і watchdog

Додано readiness gate `/api/health/ready`, який повертає HTTP 503 при UNHEALTHY, щоб успішний `curl` health-проби не означав healthy-вузол. Виправлено `/api/watchdog/report`: async handler із `await request.json()`, валідація не-dict payload і коректна серіалізація, збереження в `watchdog-reports.jsonl` (persistence/history) + HTTP contract tests.

## Monitoring: logs retrieval/retention

`read_logs` тепер читає як активні `*.jsonl`, так і ротовані резервні `*.jsonl.1..N`, фільтрує до застосування tail (`level`, `job_id`, `node_name`, `before`) і підтримує сторінкову навігацію вперед/назад через курсор `before`.

## Health: not-applicable vs required-but-unavailable

`check_postgres`/`check_redis`/`check_gpu`/`check_core_api` повертають `None` (not-applicable) для незаданих/ненаявних компонентів замість хибного `True/skipped`, а `False` лишається для обовʼязкового, але недоступного компонента.

## Security: redaction і security check

Додано `secret_redact()` у `JsonFormatter` та redaction у `ingest_logs`, щоб secret-подібні значення (access_token, api_key, client_secret, refresh_token, bearer тощо) не потрапляли в логи у failure paths; покрито синтетичними secrets. Розширено `/api/security/check`: показує слабкі env values, стан sealed encrypted secret-store, статус TLS/сертифікатів і readiness integrations.

## RBAC / admin fix

Головний адміністратор інсталяції зберігає роль `admin` навіть якщо в записі/сесії застаріла `viewer` роль (`core/security.py`). `web-v2` session/profile/guard узгоджено: некоректна сесія (без user або невідомої ролі) веде на login, а admin бачить Settings навіть при помилці повторного запиту профілю.

## Тести та інфраструктура

`conftest.py` — hermetic `CONFIG_ROOT`/`STORAGE_ROOT` з `installation.json`, щоб обійти First-Run 503 guard для всієї suite; reset alert store між тестами. Додано `tests/test_monitoring_api.py` (watchdog, readiness, health semantics, alert lifecycle/retention, redaction, logs) та `tests/test_primary_admin_role.py` (RBAC admin fix).
