# Vertep 0.0.4.23

- Локальний воркер CORE-сервера реєструється як вузол із mTLS-сертифікатом і ходить до CORE через proxy: раніше кожен його heartbeat отримував 401, тож на установці з одним сервером не було вузлів, модулі не активувались, а завдання стояли в черзі (рішення власника 20.11.2026).
- Агент оновлення в A/B-слоті (#514) читає версію й `.env` установки, а не слота: перевірка оновлень більше не падає з «Current version is older than the supported upgrade path».
- Telegram: id чату й повідомлення передаються в PostgreSQL як текст — створення завдання з бота більше не падає з «operator does not exist: text = bigint».
- Повноцінні релізи модулів: образ модуля і підписаний Ed25519 `package.json` (маніфест з образом за digest, міграції, UI) у релізі `<модуль>.<версія>`; релізи 0.0.4.15 дозбираються пакетами; ключ видавця `vertep` у `config/module-trust/publishers.json`.
- Monitoring 0.0.4.16: сторінка модуля без CDN — Chart.js 4.5.1 і стилі вбудовано, працює в ізольованому iframe.
- Модулі: Web UI — системний компонент (стан контейнера, без дій установки); помилка дії показується в картці модуля; права офіційного модуля можна погодити до встановлення; FAILED-розгортання попередньої версії та його алерт більше не висять після оновлення.
- Резервні копії: адміністратор може повторно завантажити ключ шифрування з підтвердженням паролем, записом у журнал SECURITY та алертом.
- Реальні тести: S02, S07, S08 прибрано (їхні issue закриті); S03 на стенді без GPU — «Не застосовно»; «Не переведено» → «Ручна процедура (не автоматизовано)»; перелік issue звірено з GitHub (#441, #442, #516), CI перевіряє розбіжність.
- Оновлення: банер підготовки показується лише коли є оновлення; завдання без workflow підказує, що використано демо-workflow.
