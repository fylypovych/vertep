# Vertep 0.0.2.6

- Issue #75 S1: додано єдиний валідатор session identity `web-v2/src/app/core/session-identity.ts` (`resolveSessionIdentity`/`requireSessionIdentity`); валідна identity — лише `authenticated: true`, непорожній login і відома роль `admin|viewer`.
- Issue #75 S1: `SessionApiService.profile` більше не підвищує невідомі або відсутні ролі до `admin`; обидва clients, `AuthGuard`, `AdminGuard`, login і header використовують спільний валідатор.
- Issue #75 S1: `POST /api/session` не випускає admin-сесію для непідтверджених облікових даних — неправильні credentials повертають `401`; `core/security.py::_account_role` не підвищує невідомі ролі, вони деградують до `viewer`.
- Issue #75 S1/S6: публічна оболонка SPA (`/`, `/login`, `/v1/`) доступна без автентифікації, щоб guard-redirect мав куди вести; `/api/*` залишається захищеним (тест `test_login_shell_is_public_while_api_stays_protected`).
- Issue #75 S3: профіль отримав self-service поля `display_name` та `email` з серверним збереженням (`PUT /api/session/profile`, `core/security.py::save_account_profile`).
- Issue #75 S3: зміна власного пароля (`PUT /api/session/password`) з серверною password policy, перевіркою поточного пароля та відновлюваними помилками без розширення account scope.
- Виправлено UTF-8 Basic authentication: `AuthApiService` більше не використовує `btoa` (кирилиця кидала `InvalidCharacterError` і сторінка login зависала); додано спільний `basicCredentials()` на `TextEncoder`, який використовують обидва clients.
- Виправлено неASCII-безпечне порівняння credentials: `secrets.compare_digest` не приймає не-ASCII `str`, що давало `TypeError`; додано `core/security.py::_constant_time_equals` (порівняння UTF-8 байтів).
- Виправлено session token для неASCII-логінів: payload cookie тепер percent-encoded і не ламає розбір на `:` (`_session_token`/`_valid_session`), оскільки first-run wizard допускає Unicode-імена.
- Локальні запусти більше не пишуть поза проєктом: `CONFIG_ROOT`, `STORAGE_ROOT`, `UPDATE_STATE_DIR`, `JOB_ROOT` мають проєктний фолбек на Windows (`core/first_run.py`), а `pg_dump` пише у `var/tmp`; Linux-апаратні шляхи `/data/*` не змінені.
- CI: workflow `Browser E2E` готує несекретні E2E-облікові записи через `USERS_JSON` і передає `VERTEP_E2E_STATE_DIR`, щоб browser acceptance виконувався на реальному локальному backend.
- Тести: 3 немоковані browser E2E на реальному CORE (profile/password/logout, viewer без admin-достуку, system-state з прямими API-перевірками 401/403/423), контракти identity/profile/password, статичний контракт відсутності role-fallback і тест UTF-8 credentials.
- Перевірка: `python -m compileall -q core adapters worker scripts installer services tests`, `python -m pytest -q` (937 passed, 74 skipped), `web-v2` Playwright `session.spec.ts` + `rbac.spec.ts` (20 passed), `npm run build`, `git diff --check`.
