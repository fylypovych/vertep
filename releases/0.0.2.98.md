# Vertep 0.0.2.98

- `tests/conftest.py`: фікстура `signed_update_server` — справжній HTTPS-сервер оновлень з RSA-підписаними маніфестами; update-agent сам перевіряє підпис, sha256 і replay (#387 F1).
- `tests/test_core_rollout_coordinator.py`: сценарії rollout більше не підміняють `validate_manifest`/replay; додано перевірку, що підроблений маніфест відхиляється до будь-якої мутації й не перезапускає runtime (#387 F1/F2).
- `tests/test_standard_host_consumer_docker.py`: штатний `scripts/vertep` з update-agent проводить Worker у Docker через update (з переходом зі старої плоскої інсталяції), restart і rollback; перевіряються заміна контейнера, версія й образ з самого контейнера, кореляція з операцією, хеш даних споживача; підроблений реліз і невдале перенесення legacy-інсталяції не чіпають контейнер (#387 F1/P1).
- `tests/test_update_operation_lifecycle.py`: Telegram-операція оновлення проходить помилку, повтор і успіх на справжньому маршруті executor; звірку і сповіщення робить окремий перезапущений процес CORE (#387 F3).
- `tests/test_update_browser_e2e.py`: Update Browser працює зі справжнім підписаним каналом, перевіряє повтор після відкату і показ результату після рестарту процесу CORE (#387 F3).
- `tests/test_backup_process_acceptance.py`: відмови відновлення через CORE для чужого snapshot/файлу та часткового архіву, повтор з тим самим токеном, невдала віддалена копія без успішного receipt (#387 P3).
- `scripts/qualify_bootstrap_lifecycle.py`, `tests/test_qualify_bootstrap_lifecycle.py`: матриця довіри executor виконується всередині контейнера `linux/<arch>`, у звіт записується архітектура процесу, що виконує тести; B2 PASS лише без пропусків (#388 B2).
- `.github/workflows/ci.yml`: Docker-тести штатного consumer обов'язкові в `fleet-persistence-runtime-acceptance`; job `bootstrap-lifecycle-acceptance` має таймаут 60 хв і вивантажує докази з контейнера.
