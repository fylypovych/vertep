# Vertep 0.0.3.36

Виправлення за аудитом: i.0.0.4.9–i.0.0.4.12 (#409–#412) та залишки #404–#408.

- Оновлення: створення job заблоковано в `UPDATING` і `RECOVERING`, зокрема через Telegram; rollback стирає БД лише для релізу з `rollback_safe=false`.
- Worker: `update-agent.py` став єдиним виконавцем оновлення і не чекає drain на worker-вузлах; `worker_update.py` і його units видалено.
- Publisher: Telegram виконується Worker-ом; Instagram завантажує файл без публічної адреси; Threads отримує підписане посилання з обмеженим строком; Instagram, Threads і Facebook читають посилання на пост з API; збій читання посилання не спричиняє повторну публікацію.
- Адмін-панель: новий розділ «Публікація» з публічною адресою Vertep і каналом Telegram; у вікні job кнопка «Редагувати» враховує права.
- Секрети: сховище перенесено в PostgreSQL, файл видаляється після перевірки; вузли отримують секрети через CORE лише для каналу поточної задачі.
- Безпека: токен бота Telegram маскується в текстах помилок.
- Реліз позначено `rollback_safe=false`, щоб відкат повертав сховище секретів разом із БД.
- `AGENTS.md`: уточнено правила для нових функцій, команди `пуш` і зберігання секретів.

Реальний PostgreSQL і робота на кількох серверах не перевірялись на стенді.
