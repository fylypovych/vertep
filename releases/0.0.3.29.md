# Vertep 0.0.3.29

- Telegram: порожній список чатів більше нікого не пускає; `/retry`, `/cancel`, `/approve`, `/publish` лише для адміністратора; кнопки перевіряють чат; webhook вимагає секрет; некоректне оновлення не блокує наступні.
- Backup: `backup-service` отримав пароль бази й адресу CORE; Redis копіюється та відновлюється поключово; `backup.key` не входить у копію; перед відновленням створюється копія поточних даних; tmpfs 512 МБ, дампи на диску, копія понад 512 МБ розбивається на файли.
- Оновлення: `vertep update` показує перебіг до результату; `GET update/readiness` лише читає, дренаж виконує `POST /api/system/update/drain`; watchdog не перезапускає сервіси через невдале оновлення й під час оновлення; кнопка «Оновити» потребує підтвердження й прав.
- Оновлення старих установок записує `DEMO_MODE=false`; `REQUIRE_UPDATE_KEY_LIFECYCLE=true` вмикається під час встановлення й оновлення.
- Web UI: вікно завершення налаштування після оновлення; майстер отримав кроки Telegram і ключа резервних копій; перемикач «Статичний / Динамічний workflow» (типовий статичний) і значки пояснень біля перемикачів.
- Динамічний workflow: шаблон `deploy/workflow-definitions/standard.yaml`, передача результатів між кроками `worker/workflow_inputs.py`; встановлення його не вмикає, реальний сервер не перевірявся.
- Черга: задача видаленого Job більше не ламає `claim_task`. Worker надсилає `scheduler_tags`. Voice: вузол без каталогу голосів не вважається готовим.
- `AGENTS.md`: Issue з перенесеним залишком закривається як `not_planned`.
