# Vertep 0.0.4.20

- Компонентні версії (#510): реєстр компонентів, версії `A.B.C.D` з переносом після 99, теги `<component>.<version>`, підписаний маніфест компонентного релізу, вибір тестів за впливом зміни, workflow компонентних релізів (публікація вмикається змінною `COMPONENT_RELEASES_ENABLED`; компонентний реліз ніколи не стає latest). Модулі отримали перші незалежні номери за історією (звірено з таблицею #509; відповідність «спільний реліз → версія → digest» — `config/component-transition.json`). AGENTS.md §2.20.
- Джерела модулів (#511): встановлення з Module Registry або GitHub URL, оновлення лише із закріпленого джерела, перевірки стабільності, підпису, хешу, сумісності, залежностей і вразливостей, профілі доступу minimal/standard/elevated, кеш пакетів на CORE, підписаний фід вразливостей і автоматичне блокування за підтвердженою критичною загрозою.
- Update Manager (#512): план із версіями, етапами за залежностями й вузлами, погодження перед виконанням, паралельні незалежні модулі й послідовні вузли, перевірки контейнера/API/БД/залежностей до READY, відкладені вузли з повторною перевіркою після reconnect, спільний план CORE + модуль, відновлення сумісного набору.
- Відновлення оновлень (#513): блокування записів після drain, перевірені snapshots, повторна доставка без подвійного застосування, рівно один автоматичний повтор і зупинка з тривогою адміністратору, точки ручного rollback з підтвердженням втрати пізніших записів, зберігання активної та двох попередніх версій, окреме повне очищення архівів.
- A/B Update Agent (#514): два перевірені локальні слоти агента; перемикання лише після локальної перевірки готовності, Watchdog повертає попередній слот, недоступний CORE не відкидає робочий слот.
- Панель Updates (#515): рекомендації з оцінкою ризику, план/погодження/запуск через Update Manager, прогрес, точки rollback, категорія UPDATE у журналі з прив'язкою до операції.
- Інструкції для тестових агентів реальних перевірок: `AGENTS-GPU.md`, `AGENTS-NOGPU.md`.
