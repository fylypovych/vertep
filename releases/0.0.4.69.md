# Vertep 0.0.4.69

- Стабілізація встановлення (#553): валідний WAV від TTS і health бекапів (AC1–AC2); startup-recovery без повторного розгортання, операції оновлення з Web UI в журналі, readiness дренажу прив'язана до поточної операції (AC3–AC4); звичайні GET налаштувань і рекомендацій модулів не роблять мережевих probe — живе оновлення лише з `?probe=true`/`?refresh=true` (`core/read_cache.py`, AC5); статичний режим workflow на чистій інсталяції (AC6–AC7, AC11); заголовки безпеки й HSTS для Web UI (`deploy/proxy.conf*`, `docker/web-ui/nginx.conf`, AC8); одна політика паролів для First Run і `/api/security/check` (AC9); ComfyUI не перевіряється на вузлі без ролі gpu (AC10). Тести `tests/test_issue_553_*.py`.
- Відновлення з копії (#555): готовність після restore чекає свіжого heartbeat воркера, а не падає в EMERGENCY через прострочений heartbeat зі старого знімка; heartbeat дозволено під час RECOVERING (`core/api/auth.py`, `tests/test_backup_restore_heartbeat_555.py`).
- Безпека сесій (#556): активні сесії користувача відкликаються при видаленні облікового запису, пониженні ролі чи зміні пароля (`core/security.py`, `core/api/users.py`, `tests/test_session_revocation_556.py`).
- LAB (#546): оцінювання моделей — в окремому образі `deploy/lab/Dockerfile.eval`; оновлено compose і `bootstrap-lab.sh`, документацію `docs/lab.md`.
- Компонентні релізи: запуск без змін між base і head (наприклад, ручний з base = поточний commit) тепер завершується помилкою, а не зеленим «порожнім» run (`.github/workflows/component-release.yml`, `tests/test_components.py`); оновлено класифікацію (`scripts/component-release.py`, `core/components.py`, `config/components.json`).
- Новий щотижневий workflow «GitHub Cleanup» (понеділок 00:00 за Києвом): видаляє workflow runs, що не пройшли, крім найновішого run кожного workflow, і залишає 4 релізи Vertep — останній і три попередні, повністю зелені (CI, Browser E2E, Vertep Release); Git-теги видалених релізів зберігаються (`.github/workflows/github-cleanup.yml`, `scripts/github-cleanup.py`, `tests/test_github_cleanup.py`).
- Тести: `test_sidebar_settings_order` враховує `moduleItems` як `computed` після змін навігації #554 (CI 0.0.4.68 падав на ньому).
- Документація: компонентні релізи, UpdateManager, snapshots і retention у `docs/update-system.md`; контракт модуля; правила стислості відповідей в `AGENTS.md`.
- Оновлення модулів (#553 AC5): кеш рекомендацій тепер зберігається між запитами (раніше кожен GET створював новий `ModuleSources` і повертав порожній список), скидається після нового закріплення джерела; панель «Оновлення» повторює запит, поки CORE оновлює кеш. Тести TTS використовують справжній WAV, `publishers` визнано локальним пакетом образу CORE.
