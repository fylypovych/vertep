# Vertep 0.0.3.73

- Text Worker (#465, `i.0.0.4.65`): production task `script` виконує Structure → Scenes → Assembly — окремий запит структури, окремий запит на кожну сцену, збирання через `normalize_script`/`ScriptDocument`; невалідна сцена перегенеровується окремо до `SCRIPT_SCENE_MAX_ATTEMPTS` (типово 3), помилки структури/сцени/backend не маскуються; конфіг персонажа й `revision` передаються в кожен етап.
- Provider Layer (#466, `i.0.0.4.66`): `execute_script()` викликає `providers.llm()` замість прямого Ollama; `DefaultLLMProvider` обирає backend за `VERTEP_LLM_PROVIDER` для кожного task; непідтримуваний backend або OpenAI-сумісний без ключа дає явну `LLMBackendError` без переходу на Ollama чи demo; Worker відхиляє доставку непідтримуваного `VERTEP_LLM_PROVIDER` як невдалу активацію.
- LAB (#467, `i.0.0.4.67`): відповідь `lab/role_service.py` містить `report_only`, `code_examined`, `files_read` і `limitations` (недоступна робоча копія, лише перелік файлів, відсутні/відхилені шляхи, обрізання контексту); межі перевірки передаються в prompt; звіт моделі не є доказом PASS.
- LAB API (#468, `i.0.0.4.68`): блокуючі виклик моделі та читання робочої копії в `/invoke` виконуються поза event loop; контракт `/invoke` не змінено.
- Тести: `tests/test_script_stages.py`, `tests/test_script_llm_provider.py`, `tests/test_lab_report_context.py`, `tests/test_lab_role_service_concurrency.py`, `tests/script_llm_stub.py`; Ollama stubs process-тестів відповідають поетапно. Документація: `docs/content-pipeline.md`, `docs/providers.md`, `docs/lab.md`; додано звіт аудиту `audit/audit-1311.md`.
