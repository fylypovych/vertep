# Vertep 0.0.3.91

## Модулі (#496): адміністраторська каталог модулів і вузлів

Додано ендпоінт `/api/nodes/module-catalog`, що повертає модулі × вузли з чесними причинами сумісності. Адміністратор обирає одну пару «модуль + вузол», а внутрішні ролі, Worker-и та capabilities залишаються деталями розгортання.

- Вузол, що не може запустити модуль (потрібен GPU, недостатньо VRAM/RAM/CPU, профіль LAB вимагає окремого nonproduction VM, відсутнє runtime для bundled-функції), повідомляє причину і відмовляє в розміщенні.
- Нічого не показується як `READY` без звіту Worker і.lifecycle модуля.
- Валідація placement (`core/module/catalog.py::check_placement`) піднімає `ValueError` з причиною.
- Додано `ModuleInstanceRegistry.installed_manifest()`.

## Модулі (#498): весь монтаж — на Worker

Увесь фінальний монтаж, включаючи нативний FFmpeg (`engine_id: "native"`), тепер виконується Worker-ом.

- CORE лише формує незмінну спробу: snapshot engine/config/input, durable submit key.
- CORE ставить задачу в чергу і пізніше верифікує/імпортує результат.
- Немає CORE-side render і fallback — відсутній або нездатний Worker залишає задачу в черзі (відмова, не підміна).

## Web UI: розділ «Модулі» та оновлений мастер

- Новий маршрут `/modules` з `ModuleManagementComponent`.
- API сервіси: `ModuleManagementApiService` (catalog, lifecycle install/activate/..., placement, approval) та `CoreRuntimeApiService` (runtime state).
- Бічна панель: «Розширення модулів» замість «Ролі».
- Налаштування: видалено `RolesSectionComponent`.
- Мастер першого запуску: крок «Встановлення: CORE або вузол» з вибором модулів замість ролей вузла; опис: «Перша центральна машина встановлює Vertep із CORE і вибраними модулями. Новий сервер або VM приєднується як вузол наявної системи; модулі для нього обираються в панелі. Другий CORE або LAB автоматично не встановлюються.»
