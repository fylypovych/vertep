# Vertep 0.0.2.5

- **Issue #72 — Voice artifact contract.** Аудіо-контракт версії `audio_contract/v1` обов'язковий. Валідація винесена в `_validate_tts_contract` і виконується до будь-якого побічного ефекту: до запису файлу, реєстрації артефакту, звільнення Worker і підтвердження task. Відхилений результат не залишає прийнятого артефакту й не змінює володіння Worker.
- **Issue #72 — звіряння з task.** Обов'язкові `provider` і `voice`; `model`, `language` і `speed` вимагаються лише тоді, коли task їх фіксує. Task, який нічого не фіксує, не вимагає цих полів. Voice Worker передає `speed` у contract.
- **Issue #73 — delivery contract.** `_publish_delivery_contract` фіксує версію, шлях, sha256, розмір і mime артефакту, який Publisher Worker має завантажити. Retry після втраченого ack або перезапуску публікує той самий артефакт, а не застарілий.
- **Issue #73 — durable publish intent.** Intent записується на `Job` під час enqueue і передається в task разом з delivery contract.
- **Issue #73 — кореляція receipt.** `_match_publish_receipt` приймає, пропускає або відхиляє receipt за версією та sha256 відносно intent. Невідповідна версія або sha256 завершують канал як FAILED. Уже опублікований канал пропускається ідемпотентно без повторної черги.
- **Issue #73 — owner/lease перевірка.** `core/api/tasks.py` відхиляє publish-результат, що не належить активному task або Worker, який його володіє: HTTP 409, Worker не звільнюється, task не підтверджується, тож втрачений ack можна безпечно повторити.
- **Issue #73 — обмежений retry.** Експоненційна затримка з межами `PUBLISH_RETRY_BACKOFF_BASE` (2 с) і `PUBLISH_RETRY_BACKOFF_CAP` (60 с). Лічильник retry збільшується лише коли retry реально заплановано, тому втрачений ack не витрачає слот. Intent і лічильник очищаються після PUBLISHED і NOT_CONFIGURED.
- **Кросплатформне збереження offset Telegram.** `os.open` каталогу не підтримується на Windows, тому `_save_offset_data` падав з `PermissionError` на кожному збереженні. Додано `_fsync_directory`: durability запису перенесення гарантується на POSIX, а на платформах без каталогових дескрипторів rename лишається атомарним, а дані зберігаються.
- **Тести.** 9 нових тестів для publisher intent, receipt, idempotent skip і backoff; `TestContractBeforeSideEffects` для voice-контракту; тест кросплатформної поведінки offset. POSIX-only тести (каталоговий fsync, stub `systemctl`, host consumer зі shell-скриптом) отримали `skipif` і повністю виконуються на CI.
- **Гейт генерації.** Виправлено номер рядка в allowlist `tests/test_core_generation_gate.py` для виклику `ScriptAgent` у `core/api/job_helpers.py`.

Перевірки: `python -m compileall -q core adapters worker scripts installer tests` — exit 0; `python -m pytest -q` — 920 passed, 71 skipped; `git diff --check` — чисто.
