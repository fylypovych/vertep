# Vertep 0.0.3.74

- TTS (#470, `i.0.0.4.70`): preview і synthesis голосу виконуються через Worker dispatch — job-less задача `voice_preview` (`core/voice_dispatch.py`), Voice Worker повертає audio з `audio_contract/v1`; без готового Voice Worker — 503, timeout — 504, помилка Worker — 502, fallback у CORE немає; `synthesize_voice` прибрано з CORE.
- CORE Generation Gate (#471, `i.0.0.4.71`): gate виявляє `synthesize_voice` і Worker-виконавці, `with ... as`, `importlib`/`__import__`/`getattr`, прямі HTTP inference-запити; allowlist прив'язано до enclosing function, shared implementation `core/gpu/backends.py` — лише за умови імпорту тільки Worker; межі статичного аналізу описано в `docs/core-generation-gate.md`.
- mTLS (#472, `i.0.0.4.72`): `deploy/proxy.conf` і шаблон передають `X-Vertep-Client-DN/Serial` в усіх locations лише з перевіреного TLS-сертифіката; приймання на реальному nginx (`tests/test_proxy_client_identity.py`).
- Text Worker (#474, `i.0.0.4.74`): timeout задачі — загальний бюджет генерації сценарію; перед структурою, сценою й повтором перевіряються скасування, втрата lease і залишок бюджету.
- Персонажі (#475, `i.0.0.4.75`, #476, `i.0.0.4.76`): `did_samogon` прибрано з runtime-коду, default — з `DEFAULT_CHARACTER` (Telegram — `TELEGRAM_DEFAULT_CHARACTER`), без нього — зрозуміла помилка; неповний персонаж не показується готовим (перелік, Telegram, default); тест більше не пише в `characters/`.
- CORE (#477, `i.0.0.4.77`): хешування артефактів і storage-probe у `system_test`, запис upload/import/logo та CSR first-run винесено з event loop; хешування потокове.
- Release history (#478, `i.0.0.4.78`): відновлено `releases/0.0.3.65.md`, а також відсутні `releases/0.0.3.7.md` і `releases/0.0.2.91.md` з позначкою пізнього відновлення; історію, SHA і tags не змінено.
- LLM readiness (#479, `i.0.0.4.79`): спільне правило `backend_readiness()` для `provider_matrix` і активації конфігурації на Worker — невідомий backend не маскується під Ollama, openai без ключа не вважається застосованим.
- ScriptAgent (#480, `i.0.0.4.80`): метадані структури перевіряються контрактом Assembly до генерації сцен; `duration: null` не викликає перегенерації; `task.prompt` — додатковий brief.
- LAB context (#481, `i.0.0.4.81`): ліміти читання й переліку діють під час збору; `code_examined` лише для непорожнього вмісту; у `files_read` додано `total_bytes` і `empty`.
- Безпека (#482, `i.0.0.4.82`): `Secure` для cookies за HTTPS; `secret-store.key` створюється з 0600 від початку; ліміт спроб setup-токена — на реального клієнта за `X-Real-IP` від довіреного proxy (`TRUSTED_PROXY_HOSTS`) плюс загальна стеля `SETUP_RATE_LIMIT_GLOBAL_PER_10_MINUTES`.
- Update agent: скасування fenced-оновлення сигналізує лише групу дочірнього процесу через `os.killpg`; прибрано `kill -SIG -PGID`, який у procps-ng 4.0.4 надсилав сигнал усім процесам користувача.
- Auth: Worker-маршрути `publisher-readiness`, `model-progress`, `watchdog/report`, `nodes/{id}/self-test` доходять до власної перевірки токена вузла при увімкненій сесійній автентифікації.
- Bootstrap: `DEFAULT_CHARACTER`, переданий під час встановлення, записується в `.env`.
- Тести (#483, `i.0.0.4.83`): `test_worker_loop_survives_a_disowned_task` більше не підміняє глобальний `time.sleep`; нові тести для кожної зміни; додано аудит `audit/audit-1511.md`; `.gitignore` ігнорує локальні `.swarm/` і `.claude-flow/`.
