# Vertep 0.0.3.0

- `scripts/vertep`: під час оновлення CORE backfills виконуються через compose-сервіс `migrate` з образу нового релізу; раніше `migrate.py` запускався в старому контейнері `core` за шляхом хоста, якого там немає, тож штатне оновлення CORE через update-agent мало падати з «PostgreSQL backfills failed» (#387 F1/F2).
- `tests/test_standard_host_consumer_docker.py`: справжній Backup Service знімає дані, штатний consumer оновлює Worker, дані відновлюються, а контейнер Worker читає відновлені схвалення, квитанції й відповідності після оновлення, рестарту і rollback (#387 P4).
- `scripts/qualify_ubuntu_bootstrap.py`, `tests/test_qualify_ubuntu_bootstrap.py`, CI-job `ubuntu-bootstrap-lifecycle`: справжній `bootstrap.sh` на Ubuntu 24.04, TLS-handshake з точним сертифікатом, `/api/health` по HTTPS, оновлення сертифіката з перезавантаженням proxy і повторний bootstrap зі збереженням даних, облікових даних і сертифіката (#388 B3).
- `scripts/moneyprinter-recovery-check.py`: на справжньому pinned runtime перевіряються відмова відсутнього голосу до POST без «відновлення» через пізнє staging, повтор після повторного staging без втрати вхідних даних, скасування за ключем без видачі задачі, що виконується, за зупинену; режими `--serve`/`--stop` для pytest проти контейнера (#389 M3/M4).
- `tests/test_mpt_media_matrix.py`: з `VERTEP_MPT_PINNED_URL` ті самі тести медіаматриці проходять через справжній pinned submit/status/download; fault-injection stand-in у цьому режимі позначаються як непридатні; CI-job `moneyprinter-pinned-runtime` запускає матрицю проти контейнера з JUnit (#389 M1).
- `tests/test_text_redis_process.py`: одноразовий CORE процесного тесту має підвищений rate limit, бо опитування кожні 0,1 с перевищувало production-ліміт 300/хв і давало нестабільний HTTP 429.
- `tests/test_local_contracts.py`, `tests/test_moneyprinter_recovery_check.py`: контракт виклику backfills і логіка нових перевірок відновлення.
