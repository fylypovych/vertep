# Vertep 0.0.3.63

- Health (#449): відокремлено метадані від перевірок, локалізовано стани й причини, додано компактну історію змін без переписування минулих відмов.
- Ролі (#450): polling і reload відновлюють requested/applied/runtime-стани, показують етапи й помилки executor; додано ідентифікацію запитів, захист від конфліктів і перевірки готовності.
- Додано локальну команду vertep remove (#446) для runtime з ownership inventory: dry-run, підтвердження hash, окремий purge даних, захист спільних ресурсів, журнал і продовження після переривання. Legacy без inventory та спільні пакети автоматично не видаляються; повне Ubuntu/systemd-приймання не виконано.
- Документація (#448): розділено правила, актуальні настанови, acceptance, LAB і архіви; збережено нормативні §0–§4 та §16, виправлено застарілі описи й посилання.
- Bootstrap залишає вибір ролей майстру; CORE перевіряє Voice/Publisher за адресами служб; після завершення майстра запускається Telegram polling.
- DEMO_MODE вимкнено за замовчуванням; внутрішні Dispatcher/Scheduler запити автентифікуються ключем; Telegram readiness враховує налаштований канал; ComfyUI frame fallback збирає відео через FFmpeg.
- LAB перевіряє відповідність evidence ідентифікатору Issue; перенесений залишок закривається як not_planned, а не completed.
- Реальні тести показують прив’язку сценаріїв до Issues; оновлено каталог кваліфікації, навігацію ключів інтеграцій, повторне завантаження моделей і відображення довгих fingerprints у Security.
- Додано API/executor, Docker і Browser перевірки та виключено локальні Browser-артефакти з Git.
