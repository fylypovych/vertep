# Vertep 0.0.2.13

Ця версія закриває залишкові критерії приймання п'яти implementation Issues: #77 (Workflow management), #78 (Models/providers), #80 (Node deployment), #81 (Video revision) і #84 (Security).

## Issue #77 — Workflow management: forms, history та dependencies

- Розділ «Налаштування → Моделі» перероблено: показ локального каталогу Ollama разом із per-node розміщенням, готовністю вузлів, віком каталогу та керуванням pull/delete.
- Додано попередження про застарілий model-каталог і про pending-команду на вузлі, щоб оператор не вважав застарілий стан актуальним.
- Оновлено типізацію API (`settings.api.ts`, `models.ts`) під фактичні backend-відповіді.

## Issue #78 — Models/providers: lifecycle та deployment

- Додано `core/provider_switch.py`: вибір backend зберігається в overrides і застосовується при старті CORE, якщо застосування не вдалося — старт не блокується, помилка пишеться в лог.
- Додано `GET /api/settings/providers` і `POST /api/settings/providers/{slot}` з контрактом persist → apply → verify → rollback; перемикання відхиляється для не-switchable слота, невідомого backend і неконфігурованого backend.
- `core/pull_executor.py` розширено: durable operation для pull/delete, доставка команди на вузол через heartbeat, worker-authenticated канал прогресу і скасування, `PlacementError` з коректними HTTP-кодами, відновлення orphaned-операцій після рестарту CORE та інвалідація model-кэшу на disabled/revoked вузлах.
- Поля життєвого циклу моделей, якими володіє CORE, більше не затираються кожним heartbeat.
- `POST /api/models/text/pull` тепер повертає запис operation, а не синхронний результат pull.
- Додано `POST /api/models/voices/preview` з явними негативними шляхами: `409` для вимкненого або неповно налаштованого TTS, `422` для невалідного запиту чи невідомого голосу, `502` для недоступного runtime, нечитабельного каталогу або порожнього аудіо.

## Issue #80 — Node deployment: role contracts і rollback proof

- Додано outbound-only renew/revoke вузла: `renew_node` і `revoke_node` доступні зі сторони вузла, старий serial потрапляє у CRL, а старий JWT і worker secret перестають діяти.
- `renew_node` тепер повертає `certificate_serial` і `certificate_expires_at`, щоб renew/revoke round-trip був підтверджуваним, а не лише опосередкованим.
- `core/api/workers.py` віддає registry-статус `runtime_status` для записів, що пішли offline, щоб dispatch ніколи не вважав застарілий запис готовим до роботи.
- `scripts/apply-deployment.py` додано rollback attestation і перевірку здорового стану попередніх сервісів; enrollment повторює спробу при transient 429/502/503/504 і транспортних помилках.

## Issue #81 — Video revision: застосування правок і artifact identity

- Розширено переходи станів Job: `SCRIPT_REVISION_REQUESTED` може повернутися у `SCRIPT_QUEUED`, а `VIDEO_PENDING_APPROVAL` може перейти у `SCRIPT_REVISION_REQUESTED`, щоб вільний текст правки застосовувався до генерації, а не лише до монтажу.
- Перезбірка відео (`_collect_reassembly_inputs`) бере лише зареєстровані артефакти сцен: упорядковано за індексом сцени, з дедуплікацією до найновішого артефакту та перевіркою SHA256. Жодного globbing `images/`, `storyboard/`, `frames/` — там зберігаються історичні версії, а лексикографічний порядок імен неправильний (`sb-1-10` перед `sb-1-2`).
- Відсутність придатних артефактів або порушення цілісності явні: Job переходить у `VIDEO_FAILED` із зрозумілою причиною, а не мовчки збирає порожнє відео.
- Усі відео-дії (`vid_ok`, `vid_reject`, `vid_edit`, `vid_regen`) прив'язані до чату, якому належить Job; помилки перезбірки повідомляються власнику Job у Telegram.

## Issue #84 — Security: redaction, secrets та effective checks

- `secret_redact` тепер маскує URL userinfo (`https://user:pass@host`), query-string credentials (`?token=...`) та значення, що містять `:` (Telegram-токени формату `123456:AAH...`), поряд із JSON із quoted keys, bearer-токенами, вкладеними payload, traceback і Runner report.
- Audit-поверхні redacted: operation audit у `core/operations.py` та hash-chained update audit у `scripts/update-agent.py` (ланцюг hash при цьому зберігається).
- Error-поверхні API redacted: помилка probe в `/api/integrations` і помилка Runner.
- `core/first_run.py::inspect_data_key` визначає effective-стан data key. Раніше `_secret_store_status` читав неіснуючий шлях `.secret-store.key` і шукав поле `wrapped_data_key`, якого реальний конверт не пише, тому запечатаний ключ не можна було ані підтвердити, ані виявити.
- Додано `rotate_data_key` з атомарним backup попереднього ключа та відкатом, якщо перезапис сховища перервався; raw-ключ прозоро перезапечатується, коли з'являється passphrase.
- `/api/security/check` fail-closed: відсутній або непрочитний сертифікат і запечатаний ключ, який CORE не може відкрити, більше не потрапляють у `ok`; додано статуси `unreadable`/`unsealable` і тексти remediation.
- `verify_node_certificate` відхиляє прострочений сертифікат навіть із дійсним serial; непарсибельний або відсутній expiry вважається простроченим.
- Секція «Безпека» в Angular показує effective store, сертифікати з SHA-256 і датами та інтеграції з локалізованими статусами, замість лише прапорця OK.
- Додано Browser E2E на degraded і healthy стани security UI.
