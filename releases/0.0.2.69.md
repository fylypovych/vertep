# Vertep 0.0.2.69

- Issue i.0.0.2.50 (#250) — Lab: фактичне виконання, погодження та recovery-safe governance.
- `lab/executor.py` (нове): клієнт role-executor за контрактом `role-executor/1` з перевіркою ізоляції перед відправкою, fail-closed без явного endpoint, окремим повідомленням про таймаут.
- `lab/roles.py` (нове): розбір `lab/role_profiles.md` (рівно 8 профілів) і рольова матриця прав — `reviewer` лише read-only, `qa` не виконує зміни.
- `lab/policy.py`: рольове рішення `decide()`; grant прив'язаний до subject, оточення, версії scope, терміну дії та revokable; `request_rights()` ніколи не видає grant; `validate_lab_finding()` пропускає лише підтверджені дефекти; `reserve_identifier()` видає номера з єдиної серії `A.B.C.D`.
- `lab/orchestrator.py`: рольовий executor обов'язковий — без нього запуск `BLOCKED`, а не `COMPLETED`; результат реального виклику записується в звіт; lease звільняється у `finally`; стан і hand-off переживають рестарт.
- `lab/governance.py`: `create_issue()` — «ідемпотентність → duplicate check → резерв номера → gate → транспорт → тривалий запис»; `submit_ir_evidence()` вимагає version, commit, environment, expected, actual, незалежного reviewer і зелені лічильники тестів; `delegate_close_ir()` закриває `ir` лише за повним доказом; `consolidate_ir()` виконує порядок §4.7 (plan → authorise → create → перевірка зв'язків і повноти → close джерела) без втрат і дублів; `probe_surface()` пояснює відмову без побічного ефекту.
- `lab/governance.py`: `GitHubApiTransport` і `default_transport()` — реальний транспорт поверх GitHub REST API з налаштованим `LAB_GITHUB_API_URL`; без токена й репозиторію транспорт лишається dry-run.
- `lab/api.py`, `lab/cli.py`: видача grant і revoke вимагає автентифікації власника (`LAB_OWNER_TOKEN` + `X-Lab-Owner-Token` / `--owner-token`), `approved_by` береться з автентифікованої особи `LAB_OWNER_IDENTITY`; сервісні поверхні використовують `default_transport()`.
- `deploy/lab/docker-compose.yml`: `lab-control` отримує owner- і transport-конфігурацію, недовірений `lab-sandbox` — ні; агент не може видавати grant чи публікувати.
- `scripts/lab-orchestrator.py`: role-executor і resource provider резолвляться явно; без endpoint запуск блокується, fake provider вмикається лише прапорцем.
- `lab/notifications.py`, `lab/reports.py` (нові): сховище налаштувань важливості сповіщень і збірник комбінованого звіту лабораторії.
- Тести: `tests/test_lab_github_transport.py` (реальний транспорт проти контрольованого GitHub HTTP endpoint), `tests/test_lab_resource_transport.py` (10 сценаріїв client → resource API), `tests/test_lab_rights_requests.py`, `tests/test_lab_cli.py`; розширено `tests/test_lab_deployment.py` (ізоляція на постачальних compose і Dockerfile), `tests/test_lab_executor.py` і `tests/test_lab_orchestrator.py` (таймаути).
- `docs/lab.md`, `docs/lab-checklist-etap5.md`, `docs/lab-checklist-etap6.md`, `docs/lab-checklist-etap7.md`: owner-секрет замість `--approved-by`, налаштування транспорту GitHub, межі dry-run.
