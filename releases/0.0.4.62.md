# Vertep 0.0.4.62

- Модулі на CORE: контейнери application-модулів (Бренди, Персонажі, Моніторинг, Сторіборд) запускає системний виконавець хоста, а не воркер без доступу до Docker. Воркер у режимі `VERTEP_APPLICATION_MODULES=host` пише запит `config/application-modules/request.json` (підписаний пакет і токен модуля, 0600) і звітує стан зі `state.json` (`worker/application_supervisor.py`); `vertep-deployment.path` реагує на запит, `scripts/apply-deployment.py` повторно перевіряє підпис пакета власним ключем довіри хоста, запускає ізольований контейнер без порту хоста й підключає до мережі модуля лише CORE (alias `core`) і воркер; повтор через 5 хв, якщо модуль не готовий; після розгортання ролей мережі модулів відновлюються. Runtime bundle несе ключ довіри (`runtime/module-trust/publishers.json`) і `worker/application_container.py`; production compose вмикає режим `host` (`deploy/docker-compose.yml`, `installer/vertep-deployment.path`, `scripts/build-runtime-bundle.py`, `worker/application_container.py`, `tests/test_application_modules_host.py`).
- Web UI: на кроці перевірки майстра першого запуску кожна вибрана служба показує смугу прогресу з етапом розгортання (очікування, підготовка, завантаження образів, запуск, перевірка) замість «Помилка» під час розгортання; у картці модуля — смуга п'яти кроків до активації, каталог оновлюється сам, поки вузол запускає модуль (`web-v2/src/app/setup/`, `web-v2/src/app/modules/module-management.component.ts`, переклади `en.ts`, Playwright-тести).
- TTS (#540): гібридний runtime Piper uk_UA (основний) + espeak-ng (запасний) у контейнері `tts` (`services/tts_service.py`, `docker/tts/Dockerfile`, `adapters/providers/tts_backends.py`).
- Video (#542): шаблони ComfyUI Wan2.2 TI2V-5B і 14B (`workflows/video/wan22-*.json`), перелік вузлів Wan2.2 в inventory образів ComfyUI NVIDIA/AMD, мінімальна VRAM задачі береться з шаблону (`workflow_min_vram_mb` у `core/workflows.py`, `core/api/jobs.py`), моделі Wan2.2 як плейсхолдери (`adapters/comfyui.py`); Dispatcher знає capabilities `speech_recognition`, `lora_training`, `avatar_lipsync` і типову VRAM для lip-sync (`core/dispatcher.py`).
- STT (#544): локальний сервіс розпізнавання мовлення на faster-whisper (`services/stt_service.py`, `docker/stt/`, `adapters/providers/stt_backends.py`).
- LAB Eval (#546): ізольовані запуски Promptfoo та lm-evaluation-harness без телеметрії й платних ключів (`lab/eval_runner.py`, `lab/eval_configs/`, `lab/cli.py`, `lab/reports.py`).
- LoRA (#548): пайплайн навчання LoRA персонажів через ostris/ai-toolkit з allowlist комерційно дозволених базових моделей (`adapters/lora_training.py`, `services/lora_trainer_service.py`, `docker/lora-trainer/`).
- Storyboard (#550): експорт таймлайнів у OpenTimelineIO (`modules/storyboard/otio_export.py`, `modules/storyboard/storyboard_module.py`).
- Lip-sync (#551): анімація аватара на MuseTalk (`services/musetalk_service.py`, `docker/musetalk/`, `adapters/providers/lipsync_backends.py`); нові служби й provider-інтерфейси в `deploy/docker-compose.yml`, `adapters/providers/`, `worker/role_executor.py`.
- Виправлення для #540/#544/#551: повна самоперевірка (`POST /api/system/test`) зіставляє нові провайдери STT і lip-sync із ролями voice і gpu, як TTS і image/video, і не вважає їх збоєм, коли ці ролі перевірено (`core/api/system.py`); `pip install` в образі TTS записано одним рядком для перевірки залежностей образу (`docker/tts/Dockerfile`); у майстрі перевірки Docker, PostgreSQL, Redis і API CORE не маскуються етапом розгортання — їхня помилка видна одразу.
