# Vertep 0.0.3.59

- Майстер першого запуску показує обладнання, підсумок інсталяції та реквізити підключення читабельними полями замість JSON. Сертифікат і контрольна сума згорнуті; повні дані інсталяції можна завантажити.
- Health Check (#445) враховує вибрані основну й додаткові ролі та AI backend. API, майстер і container readiness healthcheck використовують узгоджені перевірки; потрібна несправна служба блокує завершення, невибрана має статус OPTIONAL.
- Служби для поточного вибору майстра готує наявний deployment executor. Повторні перевірки та відновлення після помилки зберігають введені дані; причини й обов'язковість перевірок локалізовано.
- Штатний host probe перевіряє Docker daemon і GPU runtime, публікує атомарний результат із часом спостереження. CORE відхиляє відсутні, некоректні, застарілі, майбутні й негативні результати та читає їх через read-only mount без Docker socket.
- GPU device, обчислення в ComfyUI runtime, HTTP готовність ComfyUI та Worker enrollment/self-test перевіряються окремо. Компілятор nvcc не потрібен; self-test додаткової GPU ролі CORE виконує GPU workflow. Очікуваний inventory публікується до запуску Worker й очікування його готовності.
- Bootstrap перевіряє активний systemd і наявний Docker/Compose до змін та зберігає працездатний runtime. Без systemd bootstrap відмовляє до змін; Compose runtime потребує зовнішнього host supervisor. Режими й обмеження описано в docs/runtime-readiness.md.
- Observer, systemd units, reader і документація входять у підписаний runtime bundle та штатне оновлення. Додано автоматизовані failure/recovery, artifact-level і Browser перевірки. Реальні GPU/server acceptance #42/#441/#442 залишаються окремими.
